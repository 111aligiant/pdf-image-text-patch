# 二值扫描件路径：1bit 扫描 PDF 改字全量细节

配套脚本：`scripts/binary_scan_patch.py`

> 本文数值取自一次 200dpi 黑白扫描（A4 表单、1bit、整页单张图），
> 用于说明量级与判断规则，不代表任何具体文件。

---

## 一、先判断：这张图是不是二值

扫描件、复印件、传真件里有一大类是**纯二值**：像素只有 0 和 255 两个值。
判断只要一行：

```python
vals = np.unique(np.asarray(img.convert("L")))
is_binary = len(vals) <= 2 and set(vals) <= {0, 255}
```

或者看 PDF 内嵌图的位深：

```python
page.get_images(full=True)   # 元组第 5 位 bpc = 1 就是 1bit
```

**判错了会怎样**：把二值图当灰度图走位图路径，会往纯黑白里塞一个带灰度边的字。
灰度边在 1bit 世界里根本不存在，放大就是一块边缘发虚的补丁——比位置不准更显眼。

反过来，灰度/彩色扫描件硬走二值路径也不行：原本该有柔边的地方会被削成硬边，
笔画出现台阶。**先分类，再动手。**

| 载体 | 特征 | 走哪条路 |
|---|---|---|
| PDF 有文本层 | `get_text()` 非空 | 矢量路径 `pdf_field_replace.py` |
| 扫描件，灰度/彩色 | 像素值多于两种 | 位图路径 `img_text_replace.py` |
| **扫描件，纯二值** | 只有 0/255，`bpc=1` | **本路径 `binary_scan_patch.py`** |

---

## 二、为什么位图路径的招数在这里全部作废

位图路径有三件看家本事，全部是为「抗锯齿」准备的：

| 手段 | 位图路径为什么要 | 二值图为什么不需要 |
|---|---|---|
| alpha 混合写入 | 让新字边缘与原图抗锯齿过渡一致 | 二值图没有过渡像素，混合出来的灰值就是错 |
| 高斯柔边（σ≈0.65） | 原图边缘被压缩/拍摄糊过，太锐就假 | 硬边才是原图的常态，加模糊等于凭空造灰度 |
| 逐列插值重建背景 | 渐变背景填纯色会出白块 | 背景只有一个值，刷掉即可 |

所以这条路径的规矩反过来：**1bit 进，1bit 出，中间不许出现灰度。**

## 三、① 定位：列投影切字，用 `--ref-text` 对齐字符

```bash
python binary_scan_patch.py --pdf a.pdf --box 1085,385,1330,430 \
    --ref-text "2026年1月15日" --probe
```

输出每个字的墨迹框（绝对坐标）和墨量：

```
  2  x 1095..1106  w 12  y 396..415  h 20  ink 88
  0  x 1110..1121  w 12  y 396..416  h 21  ink 96
  6  x 1139..1151  w 13  y 396..416  h 21  ink 103
  年  x 1161..1186  w 26  y 393..419  h 27  ink 182
  1  x 1257..1265  w  9  y 397..416  h 20  ink 56
  5  x 1270..1281  w 12  y 397..416  h 20  ink 94
```

**坑**：`--ref-text` 的字符数必须等于切出的字形数，脚本会对不上就报错并列出实际切分。
中文字宽、字间空格、表格竖线都会影响切分，框选区域别把竖线框进来。

**数字的墨迹宽度不是常数**：`1` 只有 9px（左右留白大），`0`/`2`/`5` 是 12px，`6` 是 13px。
字高倒是齐的（20~21px），所以**字高是可靠的定标量，宽度不是**。

## 四、② ③ 遮除：直接刷底色

```python
A[ey0:ey1 + 1, ex0:ex1 + 1] = bg     # bg 取全图中位数
```

没有抗锯齿残留要处理，抹除框**不用外扩**——墨迹框本身加 1px 就够。
但左右边界仍不能碰相邻字：上例 `5` 的墨迹到 1281，`日` 从 1296 起，
抹除框取 `1252..1292`，两边各留 4~5px 余量。

---

## 五、④ 渲染：二值化三步，相位是关键变量

```python
# 超采样 SS=8 渲染 → 面积平均降采样 → 阈值 0.5
a = render(text, size * SS)          # L 模式灰度
a = a.reshape(h // SS, SS, w // SS, SS).mean(axis=(1, 3))
mask = a > 0.5                       # 1bit
```

**为什么必须走这一路**：直接渲染 1bit 出来的是点阵字形，笔画位置由字体栅格器决定，
不受控；先灰度渲染再面积平均，等于在模拟「扫描仪对连续调原稿做 1bit 采样」这个过程。

**相位（phase）**：渲染前把笔位平移 `kx/SS, ky/SS` 像素。同一套字体字号，
`phase=(6,2)` 和 `phase=(5,2)` 出来的二值图案，笔画能差 1~2 个像素——
在 12px 宽的数字上这是肉眼可见的差别。

**画布按 `textbbox` 收紧**。反查要跑几千次，画布从 `size*SS*4` 的方图收到实际墨迹大小，
整轮从 84 秒降到 2.6 秒。

## 六、字体反查：先按字高定字号，再比形状

和位图路径同一个原则，但二值图里字高随字号**跳变**，所以要反着解：

```
对每个 (字体, 描边):
    扫字号，找「渲染墨迹高最接近锚点字高」的那档（容差 ±1px，对不上直接淘汰）
    在这个字号下，用全部锚点字算 IoU
再对前 8 名扫 8×8 相位，重算 IoU
```

19 个字体 × 6 档描边 × 21 档字号 + 相位精修，**全程 2.6 秒**。

实测一次（锚点 `2` `0` `6`，字高 20/21/21）：

| IoU | 字体 | 字号 | 描边 | 相位 |
|---|---|---|---|---|
| 0.828 | 仿宋 simfang | 29 | 2 | 6,2 |
| 0.820 | 仿宋 simfang | 29 | 2 | 5,2 |
| 0.812 | 仿宋 simfang | 29 | 2 | 7,2 |

**0.83 在 12px 的二值字形上已经算高分**——两个像素的错位就能让 IoU 掉 0.1。
分数只做候选筛选，前 3 名都要渲染出来，和同行的其他字并排放大比一眼。

### 别让脚本替你决定字号

反查给出的字号是「墨迹高对得上锚点」的字号。贴图时**按这个自然尺寸放，不要再缩放**。
位图路径允许 ≤3% 缩放微调，这里不行：二值图缩放会重采样出灰度，再阈值化回来
笔画就断或粘，1px 的损伤在 12px 字形上占比 8%。

## 七、⑤ 对齐：锚点字 + 基线，别整串居中

```
ox = ink_left  - anchor_x      # 锚点字的墨迹左缘落在目标 x
oy = baseline  - ink_bottom    # 整串墨迹底边落在基线 y
```

**锚点选哪个字**：默认取新串的最后一个字。因为它和后面那个原字相邻，
间距最敏感；前一个字往往是"可变宽度"的（`1` 换成 `2` 就宽了 3px）。

**为什么不能整串居中**：本例 `15` 换成 `28`，整串宽度从 25px 变 26px。
按居中算，左边间距 13px、右边 12px；按锚点对齐，左右都是 14px。
差 1px 在 200dpi 上就是 0.13mm，但眼睛会抓到"这块偏了一格"。

**基线取墨迹底边，不是 bbox 底边**。数字里 `1`/`5` 的底边比 `2`/`0`/`6` 低 1px
（基线相同，字形落笔位置不同），取众数或按你要对齐的参照字取。

## 八、回填 PDF：新建页比 `replace_image` 干净

```python
pg = doc.new_page(width=src_rect.width, height=src_rect.height)
pg.insert_image(pg.rect, stream=png_bytes, keep_proportion=False)   # 传 1bit PNG
doc.set_metadata(src_metadata)
doc.save(out, deflate=True, garbage=4)
```

| 做法 | 结果 |
|---|---|
| `page.replace_image(xref, ...)` | 新插一个图像对象，旧对象变孤儿，文件 21KB → 73KB |
| **新建同尺寸页 + insert_image** | 单张图，38KB，`bpc=1` 保留，页面尺寸/元数据全沿用 |

PNG 用 `img.convert("1")` 存，PyMuPDF 读进去仍是 1bpc。传 `stream=` 就不必落地临时文件。

## 九、⑥ 校验：逐像素 diff，差异必须全在抹除框内

```python
diff = render(out, dpi=native) != src.arr
print(diff.sum(), bbox(diff))     # 还要断言 bbox ⊆ erase_box
```

| 检查项 | 判据 | 实测 |
|---|---|---|
| 差异像素数 | > 0（等于 0 说明根本没改） | 181 |
| 差异 bbox | **完全落在抹除框内** | (1256,396)-(1281,416) ⊆ 1252..1292 / 390..424 |
| 页面尺寸 / 元数据 | 与原件一致 | 595.44×842.4pt，creator 沿用 |
| 图像位深 | 仍为 1bpc | 是 |

「差异跑出抹除框」是这类脚本最容易犯的错——贴图偏移算错一位，就会把相邻字的
一列像素刷白。这条断言比任何肉眼检查都可靠。

## 十、清晰度别造假

源件 200dpi，整页图 1654×2340。**导出就按 200dpi 出**，得到同一尺寸的 PNG。

拉到 1200dpi 只是插值放大，文件大 30 倍，一个像素的信息都没多。
"清晰度要匹配"在这种文件上等于**"别把分辨率吹起来"**——二值图放大后要么保持
方块，要么被平滑成灰度，两种都是破绽。

## 十一、局限

1. **只适合二值图**。灰度/彩色扫描件走位图路径，硬套这条会削掉原本该有的柔边。
2. **多字粘连**。笔画密的中文小字在低 dpi 下容易粘成一坨，列投影切不开。
   遇到就缩小 `--box` 到能切开的范围，或改用人工给定每个字的 x 区间。
3. **斜体/手写体**。脚本假定水平排版、正体、单行。手写内容基本无解。
4. **字体对不上就是不像**。0.83 的 IoU 意味着大约 17% 的墨迹像素不一致，
   在 12px 字形上肉眼能看出"这个数字和旁边的不太一样"。想要完全一致，
   只能从原件里抠同字形的像素复用（如果原件里正好有那个字）。
5. **重建页面会丢原始 PDF 结构**。原件如果是多图叠加、带注释或表单域，
   重建后这些都没了。这类文件请先在副本上验证。
