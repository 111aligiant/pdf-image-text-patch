# 位图路径：截图改字全量细节

配套脚本：`scripts/img_font_match.py`（字体反查）、`scripts/img_text_replace.py`（改写）

> 本文数值均为示意，用于说明量级与判断规则，不代表任何真实图片。

---

## 一、总原则：只改必须改的那几个字符

要改 `12:34` 里的 `34`，就**只抹掉 `34`**，`12:` 和后面的内容一个像素都不碰。

理由：锚点字原样保留，"像不像"由原图自己保证。整段重画要同时赌中字形、字重、
字距、基线，翻车概率高一个量级。

副作用是好事：字体匹配只需对**已有的几个字形**做，不必凭空猜。

---

## 二、① 定位：出掩膜 + 列投影

文字通常有明确颜色。以蓝色文字为例：

```python
mask = (B - R > 50) & (B > 100)     # 逐像素
```

**坑**：阈值放宽到 `B - R > 30` 会把浅色的背景线条（地图道路、表格线）吸进来，
整段字符粘成一坨，列投影切不出字。宁可严一点。

列投影切出每个字符的 x 范围，行投影得到墨迹上下边界。示意（某次实测）：

```
1   130-143    2   147-160    :  164-168    3  171-185    4  188-201    后续字符  206-
```

数字步进 17px、字高 23px。**这些数字后面全要用**。

量墨迹框统一用 `alpha > 0.5`。用 `alpha > 0.02` 会多吃一圈抗锯齿，宽度虚胖 1~2px。

---

## 三、② 取样 + ③ 遮除：逐列插值重建背景

**不要填纯色**。渐变背景填纯色会留下一个明显的白块。

做法：

1. 抹除框上下各取 6px 干净带（确认过里面没有字/线）；
2. **逐列**取中位数（不是全图平均色，背景有纵向渐变）；
3. 在上下端点之间线性插值，铺满抹除框。

抹除框要**盖住抗锯齿边缘**，左右各外扩 1px，否则留色边。

### 抹除框的边界纪律

抹除框左边界不能碰到前一个字符，右边界不能碰到后一个字符。
上例：冒号墨迹到 168，后一个字符从 206 起 —— 所以抹除框取 `170..204`，两边各留 1~2px 余量。

---

## 四、④ 字体反查：靠打分，不靠眼睛

同一段数字，Arial / 等线 / 思源黑体的相关系数只差 0.05，肉眼分不出来，放大一看就露。

`img_font_match.py` 把这件事变成可复现的打分：

1. 抠出参考文字的墨迹（alpha > 0.5 裁边）；
2. 遍历系统字体 × 字号 × 描边宽度渲染同一串字；
3. 缩放到参考墨迹框，算归一化相关系数；
4. 按宽度偏差扣分（不然天生更宽的粗体字会被硬压进来）。

### 关键：先按字高定字号，再比形状

如果允许任意缩放去凑参考框，粗体字会赢——因为它"更黑"，相关系数天然高。
正确顺序是：每个 (字体, 描边) 组合先解出「自然墨迹高度 = 参考高度」的字号，
再比形状。

三阶段（几百个字体全量跑要几分钟，必须分层）：

| 阶段 | 超采样 | 做什么 | 耗时 |
|---|---|---|---|
| 粗搜 | 2× | 每个字体扫字号，描边固定 0，留前 12 | 数秒 |
| 精修 | 4× | 前 12 名扫描边 0~8，字号按字高解 | 数秒 |
| 复算 | 6× | 前 3 名重算，给准确的自然墨迹尺寸 | 1 秒内 |

几百个字体总耗时约 8 秒。

### 分数只是候选，不是判决

**前 3 名都要渲染出来比一眼。** 实测分数差 0.01 以内基本是噪声，
真实差异要靠放大看字形（数字 2 的转折、9 的圈形、0 的圆度）。

示意：参考串墨迹 72×23px，笔画 4.0px / 字高 0.174（接近 bold），候选前三：

| 字体 | 字号 | 描边 | 自然墨迹 | 相关系数 |
|---|---|---|---|---|
| FRAMDCN | 33.1 | 1 | 73.2×23.2 | 0.905 |
| Dengb（等线粗体） | 32.1 | 1 | 76.3×23.0 | 0.904 |
| bahnschrift | 30.4 | 2 | 69.7×23.0 | 0.894 |
| Deng（等线常规） | 30.0 | 5 | 68.2×23.0 | 0.87 左右 |

几个候选放大后往往都能用，最后按"哪个字形更像旁边的锚点字"定。

### 字重必须靠描边补

原图字重常常比常规体粗。**只换字体不补 `stroke_width`，数字一定偏细**，放大一眼看穿。

`stroke_width` 是超采样尺度下的参数：`SS=6` 时 `stroke=6` ≈ 每边 1px。
目标是把渲染后的笔画宽度调到参考值（上例 4.0px）。

## 五、⑤ 写入：目标尺寸别硬凑，先看自然尺寸

渲染流程：超采样 6 倍渲染 → 缩放到目标墨迹框 → alpha 混合。

- **alpha 混合，不是硬贴**。硬贴会留硬边；alpha 混合出来的边缘和原图抗锯齿一致。
- **墨迹左上角直接对齐目标墨迹左上角**，不用 bbox（bbox 含字形留白，数字 1 能差 1.3pt）。
- **缩放 ≤ 3%**。各向异性拉伸会把笔画拉粗或拉细。

选参数的顺序：先让**自然宽高比**贴近目标，再用小缩放微调。

| 参数 | 自然墨迹 | 目标 31×23 | 结论 |
|---|---|---|---|
| size=32 stroke=6 | 32.33×24.67 | 需压 4% / 7% | 竖压太多，看着偏胖 |
| size=30 stroke=5 | 30.00×23.00 | 仅横向拉 3% | ✅ 采用 |

**压太狠会把字形搞坏**：压到 `30×21` 那档，`2` 的墨迹宽度反而从 14 涨到 16。
超过原尺寸 5% 就该改 `--size`，不是硬压墨迹框。

## 六、柔边：为什么改完"一眼看出是贴上去的"

字体、字号、位置全对齐了，还是假。两个隐藏原因。

### ① 边缘太锐

原图那块字被拍过/压过，边缘过渡是钝的；渲染出来的是干净的抗锯齿边。
用「平均梯度」量同一张图：

| 字形 | 平均\|梯度\| | 最大梯度 | 过渡像素数 |
|---|---|---|---|
| 原图 `1` `2` | 0.30 / 0.29 | 0.64 / 0.63 | 228 / 198 |
| 原图 `3` `4` | 0.28 / 0.30 | 0.62 / 0.77 | 179 / 169 |
| **未加模糊的新字** | **0.42 / 0.44** | **0.84 / 0.91** | **117 / 142** |

补 **高斯 σ=0.65px**（作用在 alpha 上，不是整张图）后落回原图区间。

**σ 别拍脑袋，按梯度扫**：

| σ | 结果 |
|---|---|
| 0 | 太锐，一眼假 |
| 0.65 | 对齐原图 ✅ |
| 0.85 | 比原图还糊 |

### ② 文字色偏灰

最初按"最暗像素"取色得 `(48,110,194)`，偏灰。
改用「与背景欧氏距离最大的前 3% 像素取中位数」，多个字形一致给出 `(44,108,203)`——
B 通道差 9，肉眼就是"这块颜色发闷"。

**JPEG 会在笔画芯部产生过冲**，所以"最暗像素"取到的是过冲值，不是真色。

### ③ JPEG 色度抽样（查了但别用）

原图常是 4:2:0（SOF 里 Y=0x22、Cb/Cr=0x11），彩色文字的色度边缘本来就被降采样过一次。

但实测重新按 4:2:0 存**反而更糟**：8×8 色度块边界产生台阶，最大梯度冲到 0.92。
**结论：新图按 4:4:4 存（`--subsampling 0`），柔度全靠 alpha 模糊补。**

## 七、尺寸"量着一样、看着偏大"

有时新字墨迹框和原图完全一致（都是 15×23，基线相同），看着还是偏大。

原因不是尺寸，是**字体的视觉面积更大**——墨量 186/209 对 191/194，某个数字多 8%。
**墨量比墨迹框更能反映"看着大不大"。**

修正：直接缩墨迹框，**缩的时候钉住基线**（底边不动、顶边下移），
这样字仍坐在同一条基线上，只是矮一点。

| 墨迹框 | 实测 | 墨量 | 观感 |
|---|---|---|---|
| 31×23（对齐原图） | 15×23 / 15×23 | 186/209 | 偏大 |
| 31×22 | 15×22 / 15×22 | 179/201 | 几乎没变化 |
| **30×22** | **14×22 / 14×22** | **177/193** | ✅ "小一点点" |
| 30×21 | 16×21 / 14×21 | 170/185 | `2` 被横向拉宽，比例坏掉 |

## 八、⑥ 校验：四项硬指标

| 检查项 | 判据 | 示意实测 |
|---|---|---|
| 旧字已清除 | 抹除区「蓝偏」（B−R 最大值）< 40 | 26.5（原文字处 >120） |
| 只改了该改的地方 | 目标区外全图最大差异 < 15、均值 < 1 | 14 / 0.53（纯 JPEG 噪声） |
| 没把字压淡 | 峰值 alpha = 1.0 | 1.0 |
| 观感一致 | 8 倍放大逐字比对笔画/字高/基线/颜色/柔度 | 人工确认 |

「目标区外差异」这步很容易漏。它同时证明两件事：没改坏别处，
以及重编码损失可以忽略（三百万像素里只有一百多个像素差 > 8）。

## 九、一次完整调用

```bash
# 反查字体（约 8s）
python scripts/img_font_match.py --img a.jpg --box 120,1140,210,1180 \
    --text "12:34" --target "39"
# -> 最匹配 Deng.ttf size=30 stroke=5；--target '39' 自然墨迹约 30x23

# 改写
python scripts/img_text_replace.py --img a.jpg --out b.jpg \
    --erase 170,1145,205,1180 \
    --ink 171,1150,30,22 \
    --text 39 --font C:/Windows/Fonts/Deng.ttf --size 30 --stroke 5 \
    --fg 44,108,203 --blur 0.65 --subsampling 0
```

参数含义：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--erase` | 必填 | 抹除框 x0,y0,x1,y1（右下开区间），要盖住抗锯齿边 |
| `--ink` | 必填 | 目标墨迹框 x,y,w,h，底边应落在原基线 |
| `--text` | 必填 | 新文字 |
| `--font` | Deng.ttf | 反查结果 |
| `--size` | 32 | 反查结果 |
| `--stroke` | 6 | 超采样下的描边宽度，用来补字重 |
| `--fg` | 48,110,194 | 实测芯部色 |
| `--blur` | 0 | 柔边 σ，按梯度扫 |
| `--subsampling` | 0 | 0=4:4:4 / 1=4:2:2 / 2=4:2:0 |
| `--quality` | 96 | JPEG 质量 |

## 十、局限

1. **长文本**：目标框比原位置宽很多时，得同步挪动后面的文字，当前脚本不处理。
2. **多行/旋转文字**：脚本假定水平排版、单行。
3. **强纹理背景**：逐列插值只适合平滑渐变背景；背景有纹理/文字时要用 inpaint。
4. **字形差异无法消除**：不同字体厂的数字骨架本来就不同，做到 8 倍放大也看不出需要运气。
   多数场景（手机截图、100% 观看）做到笔画/字高/颜色/柔度一致就够了。
