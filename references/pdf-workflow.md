# 矢量路径：PDF 字段改写全量细节

配套脚本：`scripts/pdf_field_replace.py`

> 本文数值均为示意，用于说明量级与判断规则，不代表任何真实文件。

---

## 一、环境与前置

| 项 | 说明 |
|---|---|
| 解释器 | 优先系统 Python。Windows 上托管解释器常缺 PDF 库 |
| 库 | PyMuPDF ≥ 1.24、Pillow、numpy |
| 字体 | 与原文匹配的系统字体文件（西文正文常用 `times.ttf`），必须真嵌入 |

不要假设机器上有 pdftoppm / ImageMagick / Ghostscript。渲染一律用 PyMuPDF 完成，
少一层外部依赖。

先跑 `--probe` 确认这个 PDF 是矢量的：

```bash
python scripts/pdf_field_replace.py --pdf a.pdf --label 编号 --value XXX --probe
```

输出会打印每页的标签 span、值 span、字号、字体、`origin` 基线，以及同列参照值的墨迹左缘。
**探不出东西就别往下走**——那是扫描件，转位图路径。

---

## 二、① 定位：用标签锚定，不硬编码坐标

- 找标签的 span，比对前先去掉所有空白（`编 号` → `编号`）。
- 在标签**同一行右侧**找值单元格。

**坑：同行不能按"垂直居中对齐"判断。**
实测遇到过标签中心与值中心差 11.6pt 的情况——表单里标签和值的基线本来就不齐。
改用 ±30pt 带状区域 + 取最左列：

```
候选   = { x0 > 标签右边 且 |y中心 - 标签中心| ≤ 30 }
最左列 = 候选里 x0 最小的那一撮（容差 2pt）
结果   = 最左列里 y 最接近标签中心的 span
```

**只取"最左列"这一步不能省**：不加它，右侧相邻列里 y 完全对齐的那个标签会被误抓。

---

## 三、② 取样：从原图取背景色

渲染目标矩形，取**出现次数最多的颜色**作为填充色。

这一步的意义：如果底色是浅灰或带底纹，硬填纯白会留下一个突兀的白块。

---

## 四、③ 遮除：redaction 真删，不是盖白块

```python
page.add_redact_annot(rect, fill=bg)
page.apply_redactions(
    images=PDF_REDACT_IMAGE_NONE,      # 不动图片 → 底图/水印保留
    graphics=PDF_REDACT_LINE_ART_NONE, # 不动线条 → 表格线保留
    text=PDF_REDACT_TEXT_REMOVE,       # 只删文字
)
```

**为什么不直接盖个白矩形**：盖白块只是视觉遮挡，旧值仍留在内容流里。
后果是复制粘贴、文字检索、OCR 会同时拿到新旧两套值，在正式文件上属于硬伤。
redaction 是把它从内容流里真正移除。

矩形向外扩 1pt，确保连抗锯齿边缘一起覆盖干净。

---

## 五、④ 写入：按原基线写入，字号自适应

- **基线**：用原 span 的 `origin`，不是 bbox 左上角。
  这样新文字和原占位符坐在同一条基线上，不会上下飘。
- **字号**：默认沿用原 span 字号。若新值比单元格宽，按比例缩到刚好放下
  （先找值单元格右侧竖线算可用宽度，找不到则按 120pt 兜底）。
- **字体**：`insert_text(fontfile=...)`，把字体真正嵌入，而不是用 base14 顶替。
  校验时看字体名是不是具体字体（如 `TimesNewRomanPSMT`），而不是 `tiro`。

---

## 六、⑤ 光学对齐：bbox 对齐 ≠ 看起来对齐

这是最容易翻车的一步。

同一列三个值的 **bbox 左边缘可能完全相同**，但肉眼看到的左边缘并不一致——
因为不同首字符的左侧留白（left side bearing）不同。示意数据：

| 字段 | bbox x0 | 墨迹左缘 | 字形留白 |
|---|---|---|---|
| `12-3456` | 223.82 | 225.15 | 1.33pt（数字 1 字身窄、居中，留白最大） |
| `98765-001` | 223.82 | 224.20 | 0.38pt |
| `ABC123` | 223.82 | 224.00 | 0.18pt（字母 A 几乎贴边） |

结果 `ABC123` 看着比上面两个**偏左约 1pt**。解决流程：

1. 按 bbox 写第一遍；
2. 渲染成图，用「首个深色像素列」量实际墨迹左缘；
3. 与参照值相减得修正量 `dx`；
4. **从原始文件重做一遍**（不叠加），写入 `x + dx`。

### 参数怎么选

- `--ink-left 225.15`：**最可控**。显式给目标墨迹左缘，脚本两遍求解 dx。
  对得上参考图时，偏差可收敛到 `±0.00pt`。
- `--align-ink`：自动量同列其他值的墨迹左缘取中位数。
  **注意**：中位数会收敛到整列平均值，只适合"大致摆正"。
- `--dx 1.1`：显式偏移量。要对齐到某张参考图时用这个。

### 判断规则（先看新旧值首字符）

| 情况 | 做法 |
|---|---|
| 新旧值**首字符同类**（都字母 / 都数字） | `dx = 0`，原位替换 |
| 新旧值**首字符不同类**（`-` → `A`） | 必须给 dx，字母开头一般 `+0.8~1.2pt` |
| 原文件值列本身就不齐（偏差 > 0.5pt） | 按最靠右的值对齐，或用 `--ink-left` 人工定 |

`AB002 → AB0002` 这类首字母相同的替换不用加 dx：字形留白一致，原位替换即完全对齐。

### 量测的两个坑

- 取样带左边界**只能取 `bbox.x0 - 1.5`**。取 `x0 - 8` 会扫到单元格左侧竖线，
  竖线被当成墨迹（实测会拽偏近 5pt），结果全错。
- 参照集**要过滤掉中文 span**。汉字墨迹左缘受字形影响极大，会把中位数带偏。

### 整列的规律

`1` 开头的值墨迹明显更靠右（因为数字 1 字身窄、居中，留白大），其余在中间区间。
所以目标位置按"紧邻上一行"或"同类型字段"取，**不要用整列中位数**（会被 `1` 开头的值拽偏）。

## 七、⑥ 校验：四项硬指标

| 检查项 | 判据 |
|---|---|
| 旧值已移除 | 全文再搜不到旧值 |
| 新值已写入 | 能搜到新值 |
| 字体已嵌入 | span 字体名不是 `tiro`/`helv`（base14 回退） |
| 页面可渲染 | 能正常出图，尺寸 = 页面pt × DPI/72 |

脚本默认导出 600dpi 整页 PNG 并做尺寸校验。**整页导出，不裁剪。**

---

## 八、局限与扩展

1. **值跨多个 span**：当前只处理单 span。若值被拆成多段（`AB` + `0002`），
   需先把同列相邻 span 合并再替换。
2. **标签不在第 1 页**：脚本逐页扫描，任意页都能处理；校验只针对第一个命中页。
3. **批量处理**：加一层 glob 遍历，建议先在副本上跑、核对无误再批量。
4. **加密文件**：很多 PDF 只设了所有者口令、打开口令为空，这类文件读和改都不需要密码，
   权限位只是"请求阅读器配合"。脚本输出统一存为不加密版本。
   若原文件需保持加密，改用 `doc.save(..., encryption=PDF_ENCRYPT_AES_256, owner_pw=..., user_pw=...)`。
5. **非标准页面尺寸**：遇到过 A4 × 1.1364 这类自定义尺寸。按 A4 打印时
   PNG 的 DPI 元数据要按实际尺寸换算，不要用"实际大小"直接打。

---

## 九、动手前先想清楚

- 这类操作会把文件重写一遍：**原始字节不可恢复**，且加密状态、权限位通常会变。
- 若原件带数字签名或可在线核验的编号，改动与"原件"就不一致了，对方核验会发现。
- 对外提供时容易被识别为非原发件（元数据、加密状态、字体子集都会露痕迹）。

实践建议：单独目录存放、文件名标明改动、**永不覆盖原件**。
